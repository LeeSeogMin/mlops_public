# 피처 거버넌스 정책 초안 (실습 13.1 부속 산출물)

> 이 문서는 실습 13.1이 다루는 피처(`public_complaints` 프로젝트, `complaint_model_v1` 서비스)를
> 대상으로 한 거버넌스 정책의 **초안**이다. 소유자·부서 표기는 8장과 동일하게 가상(시뮬레이션)이며,
> 수치는 `ch13_governance_report.json`의 실측에서만 인용한다. 공공기관 적용 시 개인정보 보호법과
> 소속 기관의 공공데이터 품질관리 지침에 맞춰 각 항목을 실제 값으로 채운다.

## 1. 목적과 범위
- 목적: 재사용되는 피처를 자산으로 관리한다 — 무엇인가(카탈로그), 누가·언제·왜 접근했는가(접근·이력),
  맞는가·바뀌면 어떻게 하는가(품질·변경). 근거 문헌: 데이터 의존성 부채와 CACE(Sculley et al., 2015),
  데이터 검증 루브릭(Breck et al., 2017).
- 범위: 카탈로그에 등록된 피처 2종(`complaint_count`, `day_unmapped_rate`)과 엔티티 `district(lawd_cd)`.
  카탈로그에 없는 피처는 접근 대상이 아니다(등록이 접근의 전제).

## 2. 피처 정의와 소유
- 모든 피처는 정의(산식)·소유자·사용 목적·원천·개인정보 등급·소비자·타임스탬프 의미·TTL·버전을 보유한다.
- 소유자는 정의·품질에 책임지며, 정의 변경 시 영향 소비자에게 통보할 의무를 진다.
- 원천은 7장 일별 배치 확정 산출물이며, 갱신 주기는 일 1회(마감 후)다.

## 3. 접근 제어(RBAC)와 목적 제한
- 역할별 허용 행위를 명시한다.

| 역할 | read_definition | read_value | read_log |
|---|---|---|---|
| training_pipeline(9장 훈련) | 허용 | 허용 | 불가 |
| serving_api(10장 서빙) | 허용 | 허용 | 불가 |
| analyst(분석가) | 허용 | 허용 | 불가 |
| external_auditor(외부감사) | 허용 | **불가** | 허용 |
| 미등록 역할 | 불가 | 불가 | 불가 |

- 목적 제한: 외부감사 역할은 원시 피처 값을 조회하지 않는다 — 감사는 값이 아니라 절차·기록을 본다.
  이는 개인정보 보호법 제18조(목적 외 이용·제공 제한)의 축소 적용이다.
- 모든 접근 요청은 허용·거부와 무관하게 access_log에 기록한다. 실습 실측: 12건 중 허용 8·거부 4.
- 개인정보 등급이 상위(민감정보 등)인 피처는 개인정보 보호법 제23조(민감정보 처리 제한)에 따라
  별도 동의·법령 근거·목적 제한·접근 로그 감사·보존 기한을 추가로 적용한다(본 실습 피처는 전부 비식별 집계).

## 4. 품질 규칙(게이트)
- 피처 값은 배포·서빙 전에 다음 규칙을 통과해야 한다(공공데이터 3대 품질지표 매핑).

| 규칙 | 공공 품질지표 | 판정(실측) |
|---|---|---|
| 결측 없음 | 완전성 | 9/9 통과 |
| 값 범위(건수≥0, 실패율∈[0,1]) | 정확성 | 9/9 통과 |
| 키 유일성((lawd_cd, event_timestamp)) | 일관성 | 9/9 통과 |

- 품질 규칙은 **게이트**(계약 위반 시 차단)이며, 11장의 드리프트 감시(분포 이동 경보)와 다른 층이다.

## 5. 변경 관리
- 정의 변경은 새 버전으로 낸다. 기존 버전은 소비자가 이전을 마칠 때까지 유지한다(8.4 버전 규율).
- 변경 이력에는 요청자·승인자·사유·영향 소비자·영향 행 수를 기록한다.
- 실습 실측 예: `day_unmapped_rate`의 산식을 "미매핑/유효건수(v1)"에서 "미매핑/물리건수(v2)"로 바꾸면
  중복 제거가 있었던 2026-07-02만 값이 변한다(0.0588 → 0.0556). 영향 소비자는 `complaint_model_v1 서비스`,
  영향 행은 3행이다. 승인 없는 정의 덮어쓰기는 금지한다.

## 6. 감사 대응
- 감사 점검표는 access_log·카탈로그·품질·변경 이력에서 자동 생성한다(사람의 주장이 아니라 기록이 근거).
- 실습 실측: 10개 항목 전항 통과. 항목은 로그 완전성, 거부 사유 보유, 값 조회 인가, 미등록 거부,
  감사 역할 값 조회 0건, 카탈로그 메타 완비, 개인정보 등급 완비, 품질 3종 통과, 변경 기록 완비,
  영향 소비자 식별을 포함한다.

## 7. 폐기
- 소비자가 없는 피처만 안전하게 폐기한다. 소비자가 있으면 폐기 전 이전 계획을 세운다(영향 분석은 보충).
