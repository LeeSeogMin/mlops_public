# 재발 방지 계획 (자동 생성 — 실습 17.1)

각 사건의 근본 원인에서 재발 방지 게이트를 도출한다. 임시방편이 아니라 근본 원인을 없애는 게이트를 우선한다(§11 근본 해결).

| 사건 | 근본 원인 | 재발 방지 게이트 | 출처 |
|---|---|---|---|
| INC-08-materialize-silent-empty | 쓰기 성공 로그 ≠ 적재 완료. 적재 범위를 명시하지 않음. | 적재 후 건수 확인 게이트 + 온라인·오프라인 일관성 대조(표 8.2) | 8장 |
| INC-09-runs-uri-load-fail | 관례 경로 문자열을 손으로 조립. 쓰기 성공 로그를 신뢰. | 등록 직후 로드·예측 스모크(시나리오 4 통과가 PASS 조건) | 9장 |
| INC-10-container-path-indexerror | 모듈 레벨 경로 계산이 저장소 깊이를 가정. --rm이 실패의 잔해(로그)를 삭제. | 컨테이너 스모크 독립 게이트 + 환경 동등성(호스트=컨테이너 예측) 실측 | 10장 |
| INC-12-single-worker-saturation | 단일 워커·단일 코어 서비스율 상한. 부하는 용량을 늘리지 않고 대기를 늘린다. | 배포 전 부하 프로파일로 처리량 천장·knee 지점 측정, 자동 스케일 임계 설정 | 12장 |
| INC-14-D1-poison-isolation | (드릴 — 격리 설계의 유효성 확인) 개별 실패가 전체를 오염시키지 않도록 사유 보존 격리. | 파싱 실패 격리 + 격리 건수 모니터링 | 14장 |
| INC-14-D2-duplicate-resend | (드릴 — 전달 보증·멱등 한 쌍의 유효성 확인) at-least-once + UPSERT. | at-least-once ↔ 멱등 UPSERT 한 쌍 유지, 파티션 수 검증 | 14장 |
| INC-14-D3-api-outage-recovery | (드릴 — 부분 실패 격리·재시도의 유효성 확인) 마감/예측 분리 + pending 재시도. | 부분 실패 격리 + 재시도 큐 + 마감/예측 의존 분리 | 14장 |
| INC-15-openai-billing-429 | 인증 게이트 통과를 '사용 가능'으로 오판. 단일 벤더 종속 위험. | 생성 엔드포인트 헬스체크 + 멀티벤더 폴백 | 15장 |

## 반복 개선 체계
포스트모템 → 근본 원인(3-why) → 재발 방지 게이트 → 파이프라인에 게이트 추가 → 재검증. 이 순환이 8~16장에서 실제로 돌았다(각 장의 '실제로 겪은 오류' → 게이트 추가).
