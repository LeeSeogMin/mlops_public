# lecture 폴더 작성 원칙

`lecture/`는 학부 강의자료와 그 상세 참고 원고를 함께 두는 공간이다. 상세 참고 원고는 `lecture/docs/`에 있다. 루트 `docs/`는 2026-08-31부터 강의자료와 무관하다.

**핵심 원칙 한 문장: 압축이 아니라 선별이다.** 상세 참고 원고의 절을 하나씩 대응시켜 줄이면 어려운 내용이 그대로 따라 들어온다. 한 장에서 다룰 핵심 개념을 3-4개만 고르고, 고른 개념은 상세 원고보다 오히려 더 천천히 설명한다. 고르지 않은 내용은 "더 알아보기"에서 `lecture/docs/`의 절 번호로 가리킨다.

> 이 문서는 `AGENTS.md` §9와 짝을 이룬다. `AGENTS.md` §2(강의 교재 모드 고정 템플릿)와 §2.4(구체성·최신성 규칙, 400줄 하한)는 `docs/` 전용이며 `lecture/`에는 적용하지 않는다.

## 대상 독자와 강의계획서

**`syllabus.md`는 그대로 유지한다.** 수강 대상(3~4학년), 선수 지식, 주차 배정, 실습 구성을 이 규정 때문에 바꾸지 않는다. 바뀌는 것은 강의자료의 **서술 깊이와 담는 분량**이다.

- 강의계획서상 수강 대상은 공공정책·빅데이터·정보시스템 전공 **3~4학년**이다.
- 다만 서술은 **2-3학년이 따라올 수 있는 깊이**로 맞춘다. 수강생을 줄이는 것이 아니라, 쉽게 쓰고 적게 담아 핵심을 확실히 이해시키는 것이 목표다.
- 조직에서 예산을 편성하거나 발주 문서를 검수해 본 경험은 없다고 본다. 조직 운영 절차를 전제한 설명은 이 독자에게 닿지 않는다.
- 목표는 "많이 아는 것"이 아니라 **핵심 개념 3-4개를 자기 말로 설명하고 실습에서 눈으로 확인하는 것**이다.

## 실습은 이론과 맞춘다

**이론과 실습은 서로 가리켜야 한다.** 이론에서 고른 핵심 개념 3-4개가 실습에서 눈으로 확인되고, 실습이 보여 주는 것은 이론에 설명이 있어야 한다.

- 실습 절이 여러 개면, 이론의 핵심 개념과 이어지는 것만 본문에 남긴다.
- 이론 어디에도 근거가 없는 실습 단계·산출물 설명은 본문에서 뺀다. 뻐 것은 “더 알아보기”에 `practice/chapter{N}/` 경로로 남긴다.
- 반대로 실습은 보여 주는데 이론에 설명이 없는 개념이 있으면, 그 개념을 핵심 개념 절에 넣는다. 설명 없는 실습을 남기지 않는다.
- 실습 절에는 다음만 둔다 — 실습 목표(2-3줄), 실행 명령, 핵심 코드 3-5줄과 전체 코드 경로, 실행 결과와 대조, 필요 시 표 1개.

**다만 조정하는 것은 `lecture/chNN.md`의 실습 서술뿐이다.**

### 시작 전 준비 절

선행 조건이 `pip install` 하나로 끝나지 않는 장에는 실습 절 첫머리에 `### 시작 전 준비`를 둔다. 자동화 스크립트 한 줄과, 그 장에서 무엇이 왜 필요한지 두세 문장을 적는다.

```bash
python scripts/setup_practice.py {N}
```

이 스크립트는 Python·Java 버전, Docker 데몬, 포트, 선행 장의 산출물, 환경변수를 점검한 뒤 가상환경을 만들고 패키지를 설치한다. `--check`를 붙이면 점검만 하고 아무것도 바꾸지 않는다. 장별 선행 조건은 스크립트의 `CHAPTERS` 표에 적혀 있으므로, 실습 구성이 바뀌면 그 표도 함께 고친다.

선행 조건이 없는 장에는 이 절을 만들지 않는다. 현재 두는 장은 1(인증키 선택)·4(Docker 필수)·6(Java 17)·7(WSL2·네트워크)·10(Docker 선택)·14(Docker 필수)다.

- `practice/` 아래의 코드·데이터·산출물 파일은 수정하지 않는다.
- 실행 명령은 기존 원고의 것을 그대로 옮긴다. 새로 만들거나 바꾸지 않는다.
- `syllabus.md`의 주차별 실습 구성을 바꾸지 않는다.
- 시험이 참조하는 산출물의 설명은 자르지 않는다(`exam/`에서 먼저 확인한다).

## 원천 자료

- `lecture/docs/chapter{N}.md`: 실무교재 최종 원고 (사실·수치의 유일한 원천)
- `contents.md`: 장별 학습 목표
- `practice/chapter{N}/`: 실제 실행 코드와 산출물
- `syllabus.md`: 주차 배정과 실습 환경
- `exam/midterm.md`, `exam/final.md`: 시험 출제 범위

실무교재에 없는 사실·수치·실행 결과·법령 해석은 임의로 추가하지 않는다.

## 무엇을 남기고 무엇을 자르는가

자를 기준은 **난이도가 아니라 역할**이다. 어려워 보여도 이 과목의 뼈대인 개념은 남기고, 쉬워 보여도 실무자가 조직에서 쓰는 절차는 자른다.

| 판정 | 대상 | 예 |
|---|---|---|
| **반드시 남긴다** | 뒤 장에서 반복해 회수되는 개념 | 침묵 실패, 학습-서빙 불일치, 드리프트 |
| **반드시 남긴다** | 시험 출제 범위에 걸린 개념 | `exam/`에서 확인한 뒤 결정 |
| **반드시 남긴다** | 실습에서 손으로 확인하는 것 | 응답 JSON 구조, 결측 표기, 성공 코드 |
| **반드시 남긴다** | 이 개념이 없으면 발생하는 구체적 사고 | 결측 `"-"`를 0으로 바꿔 "대기질 좋음"이 되는 왜곡 |
| **자른다** | 등급·수준 카탈로그 | MLOps 성숙도 수준 0/1/2, 성숙도 자가 진단 |
| **자른다** | 법령 조문 번호와 예외 규정 | 개인정보 보호법 제18·23·33·37조의2 조문 대조 |
| **자른다** | 조직 운영 절차 | 발주 문장 작성, 검수 포인트, 예산·TCO 산정 |
| **자른다** | 용어 목록형 나열 | 기술 부채 3종 이름, 도구·프레임워크 이름 열거 |
| **자른다** | 민간↔공공 대조표와 "역방향" 절 | 실무교재의 비교 표 전체 |
| **자른다** | 출처·인용 자격 구분 서술 | "직접 선례/방법론 차용" 표기는 `docs/`에만 둔다 |

자른 내용은 없애는 것이 아니라 **"더 알아보기"에서 `lecture/docs/chapter{N}.md`의 절 번호로 가리킨다**. 학생이 더 알고 싶으면 찾아갈 경로는 남긴다.

한 가지 예외: 자르면 **핵심 위험 자체가 사라지는 경우**에는 절차를 빼되 위험은 한 문장으로 남긴다. 예를 들어 법령 조문 목록은 자르되, "공공 AI가 사람 대신 결정하면 시민이 설명을 요구하고 이의를 제기할 수 있어야 한다(자세한 조문은 16장)"는 남긴다.

## 분량

- **장당 320줄 이하**(문단 서술 기준). 250-300줄이 표준이다.
- 개조식 전환으로 늘어난 줄은 상한 계산에서 빼고 센다. 상한은 **다루는 개념의 양**을 재는 기준이지 줄 수 자체가 목적이 아니므로, 같은 내용을 □·○·–로 쪼개 늘어난 분량은 초과로 보지 않는다.
- 상한을 넘으면 내용을 더 넣지 말고 **개념 수를 줄인다**. 개념 4개가 300줄이면 개념 3개로 줄여 각각을 더 풀어 쓴다.
- 핵심 개념 1개당 40-70줄을 쓴다. 개념 하나가 20줄 미만이면 그 개념은 이 장에서 다루기에 이르거나, 애초에 핵심이 아니다.

## 서술 형식 — 개조식·계층형

`lecture/docs/`의 상세 원고는 문단 서술을 쓴다. `lecture/chNN.md`는 **반대로 개조식을 쓴다**(2026-08-30 사용자 지시). 학생이 화면을 훑으며 구조를 먼저 잡게 하는 것이 목적이다.

- 설명은 **계층형 개조식 항목**으로 쓴다. 여러 문장을 이어 붙인 서술 문단으로 쓰지 않는다.
- 계층 기호는 **□ → ○ → –** 세 단계로 고정한다. 마크다운 불릿(`-`) 뒤에 기호를 붙인다.
  - `- □ ...` — 절 안의 논점 하나
  - `  - ○ ...` — 그 논점의 갈래
  - `    - – ...` — 근거·예시·수치·단서
- 네 번째 단계로 더 들여쓰지 않는다. 더 나눠야 하면 □ 항목을 하나 더 만든다.
- 종결은 `~함`·`~임`·명사형으로 끝낸다. 정의문과 결론문은 뜻이 흐려지지 않게 `~이다`·`~한다`로 쓸 수 있다.
- 한 항목에 한 가지만 담는다. 두 가지를 말하고 있으면 항목을 나눈다.
- **표·그림·플로차트·코드 블록·인용 블록은 개조식으로 바꾸지 않는다.** 있는 형태 그대로 둔다.
- 표는 대조·분류처럼 표가 아니면 읽기 어려운 곳에만 쓴다. 장당 2개 이하.
- 코드는 화면에 보이는 것을 설명하는 데 필요한 3-5줄만 넣고, 전체 코드는 `practice/`를 가리킨다.
- 영어 음차 전문용어는 각 장 첫 등장 시 원어를 병기한다(프로젝트 CLAUDE.md 규칙).

## 장 템플릿

각 장은 다음 순서를 따른다. 절 번호는 1부터 빠짐없이 이어 붙인다.

1. **오늘의 질문** — 3-4개. 이 장을 마치면 답할 수 있어야 하는 질문.
2. **비유 하나** — 장 전체를 관통하는 비유 1개. 여러 개 쓰지 않는다. 비유가 기술 개념을 왜곡하는 지점을 한 줄로 밝힌다.
3. **핵심 개념 3-4개** — 개념마다 `왜 필요한가 → 무엇이 깨지는가(구체 상황) → 어떻게 막는가` 순서로 쓴다. 개념 하나가 절 하나다.
4. **실습** — `practice/chapter{N}/`의 코드로 개념을 눈으로 확인한다. 실행 전 예측을 적게 하고, 실행 후 예측과 대조한다.
5. **핵심 요약** — 4-5개 항목. 핵심 개념 수와 맞춘다. 질문을 던지지 말고 **답을 확정해 준다**. 각 항목은 굵은 글씨의 결론 한 문장으로 시작하고, 두세 문장으로 근거를 붙인다.
6. **과제** — 1개. 제출처는 LMS, 기한은 수업일 포함 7일.
7. **더 알아보기** — 이 장에서 자른 내용을 `lecture/docs/chapter{N}.md`의 절 번호로 가리킨다. 원문 링크는 3개 이하.

**넣지 않는 절(전 장 공통)**: 활동·토론, 확장 과제(선택), 체크 질문. 수업 밖에서 하는 일은 과제 하나로 모은다.

## 주차 배정과 파일 구조

파일명은 주차 번호를 붙인 `ch{주차}.md` 형식이다. 1주차 강의본은 `ch01.md`이고 12주차 강의본은 `ch12.md`다. 한 주에 상세 원고 두 장을 쓰더라도 주차용 강의본은 하나만 둔다. 상세 원고와 실습은 기존 장 번호를 유지하므로 본문에서 출처 경로를 명시한다.

4주차 `ch04.md`는 상세 원고 4·5장과 실습 `practice/chapter4`를 한 흐름으로 묶는다. 12주차 `ch12.md`는 상세 원고 13장을 중심으로 16장의 설명·이의제기 부분을 선별하며, 본 실습은 기말고사와 연결된 `practice/chapter12`를 사용한다.

**주차용 강의본에서 뺀 상세 장**: 상세 원고 12장(부하 테스트)과 17장(베스트 프랙티스)은 강의계획서에 배정하지 않았다. 내용은 `lecture/docs/chapter12.md`·`lecture/docs/chapter17.md`에 유지한다. `lecture/ch12.md`는 상세 12장이 아니라 12주차 강의본이다.

- `lecture/assets/ch{NN}/`: 강의용 그림·도식은 출처 장 번호를 유지한다

`lecture/docs/`에 실린 그림·도식은 해당 내용이 강의자료에도 있으면 그대로 가져다 쓴다. 새로 그리지 않고 `lecture/assets/ch{NN}/`에 복사한 뒤 같은 그림 번호로 참조한다. 캡션은 학부 수준으로 다시 쓰되, 그림이 실측이 아니라 구성 시나리오면 그 사실을 캡션에 밝힌다.
- `lecture/slides/`: 필요 시 강의 슬라이드 초안
- `lecture/ch{NN}.pdf`: 같은 주차 번호의 마크다운에서 만든 배포용 PDF. 원고를 고치면 다시 만든다.

각 파일은 제목 바로 아래에 `> **N주차 · 주제**` 한 줄을 둔다.

## 금지 사항

- 실무교재에 없는 실행 결과를 "예시 결과"처럼 쓰지 않는다.
- 어려운 내용을 자르면서 핵심 위험까지 없애지 않는다. 절차는 자르되 위험은 한 문장으로 남긴다.
- 시험 출제 범위에 걸린 개념을 확인 없이 자르지 않는다.
- 비유를 위해 법·규제·보안 요구사항을 단순화해 단정하지 않는다.
- `lecture/docs/`의 상세 원고와 다른 용어를 임의로 만들지 않는다.
- 실무교재의 절 구성을 그대로 옮겨 놓고 각 절을 줄이는 방식으로 작성하지 않는다.

## 기존 장을 고칠지 판정하는 기준

**현재 원고가 아래 여섯 조건을 모두 만족하면 수정하지 않는다.** 규정이 바뀌었다는 이유만으로 멀지만 다시 쓰지 않는다.

1. 본문이 320줄 이하인가.
2. 이론 부분의 핵심 개념이 4개 이하인가.
3. 삭제 대상 절(활동·토론, 관찰 과제, 확장 과제, 체크 질문)이 없는가.
4. 자르기로 한 항목(성숙도 등급표, 법령 조문 목록, 발주·검수·예산, 민간↔공공 비교표, 역방향 절)이 본문에 없는가.
5. 설명이 □·○·– 세 단계의 계층 개조식인가.
6. 실습부가 이론의 핵심 개념과 이어지는가. 이론에 설명이 없는 실습이 남아 있지 않은가.

조건을 못 맞춘 항목만 고친다. 여섯 중 네 개 이상이 어긋나면 그때 장을 다시 쓴다.

## 작성 절차

1. `lecture/docs/chapter{N}.md`와 `contents.md`의 학습 목표를 읽는다.
2. `exam/midterm.md`·`exam/final.md`에서 해당 장이 걸린 문항을 확인한다.
3. 핵심 개념 3-4개를 고르고, 자를 항목을 위 판정 표로 분류한다.
4. 개념 순서대로 작성한다. 다 쓴 뒤 줄 수를 세어 상한을 확인한다.
5. 상한 초과 시 개념을 줄인다. 문장을 압축하지 않는다.
