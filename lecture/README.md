# lecture 폴더 작성 원칙

`lecture/`는 완성된 실무교재를 근거로 학부 3-4학년용 강의교재를 만드는 공간이다. 실무교재의 내용을 그대로 줄이는 곳이 아니라, 어려운 운영 개념을 직관, 비유, 작은 예, 수업 질문으로 다시 설명하는 파생 산출물이다.

## 원천 자료

강의교재는 다음 자료를 근거로 작성한다.

- `docs/chapter{N}.md` 또는 `docs/ch{N}.md`: 실무교재 최종 원고
- `contents.md`: 장별 학습 목표와 본문/보충 구분
- `practice/chapter{N}/`: 실제 실행 코드와 산출물
- `content/research/`: 검증된 참고 자료

실무교재에 없는 사실, 수치, 실행 결과, 법령 해석은 임의로 추가하지 않는다. 필요한 경우 먼저 리서치나 실행 결과를 확보한 뒤 반영한다.

## 대상 독자

- 공공정책·빅데이터·행정학·정보시스템 관련 학부 3-4학년
- Python과 데이터 분석을 조금 접했지만, 분산 시스템과 MLOps 운영 경험은 거의 없는 학습자
- 공공 AI·데이터 시스템을 이해하고 질문하고 평가할 수 있어야 하며, 나아가 개발자로 성장할 기초를 쌓으려는 학습자

## 작성 방향

- 쉬운 말로 시작한다.
- 기술 정의보다 “왜 이런 문제가 생기는가”를 먼저 설명한다.
- 일상적 비유를 사용하되, 비유가 기술 개념을 왜곡하지 않게 한다.
- 코드는 최소화하고, 코드가 보여주는 현상을 설명한다.
- 실무교재의 전문가용 보충 내용은 학부 원고에서는 “더 알아보기”로 짧게 둔다.
- 각 절에는 수업 중 질문, 토론거리, 미니 활동을 포함한다.

## 장별 파일 구조

권장 파일명은 다음과 같다.

- `lecture/chapter1.md`
- `lecture/chapter2.md`
- ...
- `lecture/chapter17.md`

강의용 그림과 도식은 `lecture/assets/`에 둔다. 슬라이드 초안이 필요하면 `lecture/slides/`에 둔다.

## 권장 장 템플릿

각 장은 다음 흐름을 따른다.

1. 오늘의 큰 질문
2. 직관적 비유
3. 핵심 개념 3-5개
4. 실무교재에서 가져온 작은 사례
5. 코드나 시스템 흐름을 쉬운 그림으로 설명
6. 수업 활동 또는 토론 질문
7. 체크 질문
8. 더 알아보기

## 금지 사항

- 실무교재에 없는 실행 결과를 “예시 결과”처럼 쓰지 않는다.
- 어려운 내용을 삭제하면서 핵심 위험까지 없애지 않는다.
- 비유를 위해 법·규제·보안 요구사항을 단순화해 단정하지 않는다.
- `docs/`의 실무교재와 다른 용어를 임의로 만들지 않는다.
